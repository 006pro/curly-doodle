Deviations from the stock instructions (and why)
------------------------------------------------
1. TLS: this network intercepts HTTPS, so pip/HF/Anthropic failed with
   CERTIFICATE_VERIFY_FAILED. I exported the Windows trusted root + CA stores to a PEM bundle
   and pointed PIP_CERT / SSL_CERT_FILE / REQUESTS_CA_BUNDLE at it. Verification stayed ON.
2. Windows MAX_PATH (260 chars): installing `anthropic` and `torch` under the long project
   folder names failed with "[Errno 2] No such file or directory ... enable-long-paths".
   Systems 2 and 3 therefore use venvs at the short path <repo>\.venvs\ (gitignored). Same
   packages, same `pip install -e ".[dev]"`; only the venv location differs.
3. API endpoint: the course key is a Vocareum key served at https://claude.vocareum.com
   (ANTHROPIC_BASE_URL). That proxy enables the snapshot `claude-haiku-4-5-20251001` but rejects
   the bare alias `claude-haiku-4-5` ("Model 'claude-haiku-4-5' is not available for your
   organization"). System 1 pins the alias with no CLI flag, so live System 1 commands run through
   tools/live_shim.py, which rewrites only that alias to its own snapshot and then calls the
   unmodified CLI `main()`. The reviewer model `claude-sonnet-4-6` was available unchanged.
   System 2 has a `--model` flag, so I passed `--model claude-haiku-4-5-20251001` directly.
   No reference source file was edited.
4. Record mode (System 2) writes new cache files into fixtures/recorded_responses/. The two files
   it created were moved to perturbations/recorded/ so the shipped fixtures stay byte-identical
   (listing before the run: perturbations/inputs/recorded_responses_before.txt).
5. A copy of the provided calibration_report.py was placed in the System 1 solution folder so it
   runs "from the policy-pipeline project folder" exactly as its docstring says.
